# LLMs as operating systems over time
- **2023-11-23** — The LLM is better seen as the kernel process of an emerging operating system that coordinates memory and tools than as a chatbot → [[llms-are-the-kernel-of-an-emerging-operating-system]] ([[youtube-2023-11-23-intro-to-llms]] @42:06, @42:38)
- **2024-03-26** — Everyone is trying to build an LLM OS: modalities are peripherals plugged into a new CPU, the LLM itself, connected to existing software ([[talk-2024-03-26-sequoia-making-ai-accessible]] @04:05, @04:39)
- **2024-07-03** — The LLM is like a CPU working on tokens, the context window like RAM; he calls it the LLM OS and says it feels almost like the 1980s of computing ([[talk-2024-07-03-berkeley-hackathon-keynote]] @06:10, @06:49)
- **2025-06-19** — The operating system is the analogy he finds strongest, at roughly the 1960s of computing: expensive, centralised, time-shared ([[youtube-2025-06-19-software-is-changing]] @08:54, @10:34)
- **2025-12-19** — The paradigm is similar to computers of the 1970s and 80s ([[blog-2025-12-19-year-in-review-2025]] §6)

**Note:** the dates are publication dates. The 1960s, 1970s–80s and 1980s comparisons are differences of wording, each an analogy for an early stage of computing, not a change of view; so is kernel (2023) against CPU (2024, 2025). Across these sources the analogy is restated and filled in, never withdrawn ([[talk-2024-07-03-berkeley-hackathon-keynote]] @06:10; [[youtube-2025-06-19-software-is-changing]] @10:34; [[blog-2025-12-19-year-in-review-2025]] §6).
