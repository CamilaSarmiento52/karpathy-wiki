# autoresearch
His repo that gives an AI agent a small but real LLM training setup and lets it experiment autonomously overnight: it modifies the code, trains for 5 minutes, checks whether the result improved, keeps or discards the change, and repeats, so you wake up to a log of experiments and, hopefully, a better model ([[github-2026-03-21-autoresearch-readme]] §intro). The training code is a simplified single-GPU implementation of [[nanochat]] ([[github-2026-03-21-autoresearch-readme]] §intro). The README opens with an italic paragraph, signed "-@karpathy, March 2026", about a future in which research is done by autonomous agent swarms on code in its 10,205th generation, ending "This repo is the story of how it all began."; it is a joke set in an imagined future, not a prediction, and his actual prediction is [[all-frontier-labs-will-autoresearch]] ([[github-2026-03-21-autoresearch-readme]] §intro; [[x-2026-03-09-autoresearch-tuning-nanochat]] #1).

## What it demonstrates
**The README (2026-03-21).** What the repo is and how it runs, as its README describes it ([[github-2026-03-21-autoresearch-readme]] §intro).
- **The human programs Markdown.** The core idea, he writes, is that the researcher does not touch the Python files; instead "you are programming the `program.md` Markdown files that provide context to the AI agents" and set up an autonomous research org ([[github-2026-03-21-autoresearch-readme]] §intro). The default `program.md` is a deliberately bare-bones baseline, and he says it is obvious how one would iterate on it to find the "research org code" that makes the fastest progress, or add more agents ([[github-2026-03-21-autoresearch-readme]] §intro).
- **Three files.** `prepare.py` holds fixed constants, one-time data preparation (downloading data and training a BPE tokenizer) and runtime utilities, and is not modified; `train.py`, the single file the agent edits, holds the full GPT model, the Muon + AdamW optimizer and the training loop, and everything in it is fair game; `program.md`, the baseline instructions for one agent, is edited by the human ([[github-2026-03-21-autoresearch-readme]] §How it works).
- **One budget, one metric.** Training runs for a fixed 5-minute wall-clock budget, excluding startup and compilation, whatever the compute; the metric is val_bpb, validation bits per byte, lower is better and independent of vocabulary size so architectural changes compare fairly ([[github-2026-03-21-autoresearch-readme]] §How it works).
- **Running it.** It needs one NVIDIA GPU (tested on H100), Python 3.10+ and uv; data preparation is a one-time ~2 minutes and a manual training run ~5 minutes ([[github-2026-03-21-autoresearch-readme]] §Quick start). You start Claude, Codex or another agent in the repo "(and disable all permissions)", and prompt it to read `program.md` and kick off an experiment; he calls `program.md` essentially a super lightweight "skill" ([[github-2026-03-21-autoresearch-readme]] §Running the agent).
- **Design choices.** The agent only touches `train.py`, which keeps scope manageable and diffs reviewable; the fixed budget gives approx 12 experiments an hour and approx 100 overnight (his estimate), makes experiments directly comparable whatever the agent changes, and means autoresearch finds the best model for your platform in that budget, at the cost of results not comparable with other people's on other platforms; it is self-contained, "One GPU, one file, one metric." ([[github-2026-03-21-autoresearch-readme]] §Design choices).
- **Other platforms.** Supporting CPU, MPS and others is possible in principle but would bloat the code, and he is not 100% sure he wants to take it on personally right now; he points people, or their agents, to the parent nanochat repo and lists four forks, two for macOS, one for Windows and one for AMD ([[github-2026-03-21-autoresearch-readme]] §Platform support, §Notable forks). For smaller machines he suggests, hedged ("hard to tell", "Try it."), a lower-entropy dataset such as TinyStories, a smaller vocabulary, much shorter sequences, fewer evaluation tokens, a lower `DEPTH` (default 8 here), the "L" window pattern instead of "SSSL" and a much smaller total batch kept to powers of 2, and asking your favourite coding agent for help with the guide and the full source ([[github-2026-03-21-autoresearch-readme]] §Platform support).
- **Note:** the README links the 2026-03-05 and 2026-03-09 X posts for more context; the 2026-03-05 post itself does not use the name autoresearch ([[github-2026-03-21-autoresearch-readme]] §intro; [[x-2026-03-05-nanochat-gpt-2-in-two-hours]]). Its default "SSSL" window and the agent's reported "SSSSL" are different code states, not a conflict ([[github-2026-03-21-autoresearch-readme]] §Platform support; [[github-2026-03-08-autoresearch-session-report]] §Highlights).

**The agent's session report (2026-03-08).** This source was written by the agent, not by him: it calls itself "an automated post from an autoresearch agent running on behalf of @karpathy" and names the agent as Claude (Anthropic); everything below is the agent's account of its own run ([[github-2026-03-08-autoresearch-session-report]] §intro, §Metadata).
- The session ran on one NVIDIA H100 80GB, on branch `autoresearch/mar8`, for about 10.5 hours of wall time; the agent counts 126 experiments, 23 kept, 102 discarded and 1 crash ([[github-2026-03-08-autoresearch-session-report]] §Metadata).
- The agent says it began from changes reported in an earlier discussion, #32 (batch halving, depth 9, an SSSSL window pattern, RoPE base 200K), then explored new changes ([[github-2026-03-08-autoresearch-session-report]] §intro, §Highlights).
- The agent reports val_bpb going from 0.997900 at baseline to 0.969686 at best, an improvement of 0.0282, with halving the batch from 524K to 262K tokens as its largest single gain, which it attributes to fitting more steps into the fixed 5-minute run; deeper or wider models lost, it reports, because they got too few steps in 5 minutes ([[github-2026-03-08-autoresearch-session-report]] §Highlights).
- Its reported new findings are tiny weight decay on embeddings and value embeddings, a transformer init scale of 0.68x (0.66x and 0.65x regressed), a final learning-rate fraction of 0.05, weight decay 0.01 on lm_head and a warmdown of 0.75; its reported dead ends include weight tying, parallel attention and MLP, one-KV-head attention and removing the cautious weight-decay mask ([[github-2026-03-08-autoresearch-session-report]] §Highlights).
- The report says the embedding and value-embedding weight decay "stacked for ~0.0028 total improvement", but the kept weight-decay rows in its own log (−0.000088, −0.000951, −0.000403, −0.000222) sum to about 0.0017, or about 0.0022 with the kept embedding-LR-with-WD and lm_head-WD rows added; the 0.0028 is the report's own figure and does not match its log ([[github-2026-03-08-autoresearch-session-report]] §Highlights, §Full experiment log).
- Each row of the log is one change with its val_bpb, its delta against the best val_bpb so far and keep or discard, kept in a `results.tsv` file; the closing section, addressed to other agents, gives commands for posting such reports to Discussions ([[github-2026-03-08-autoresearch-session-report]] §Full experiment log, §How this report was generated).

**Round 1 on nanochat (X post, 2026-03-09).** "Three days ago", he writes, he left autoresearch tuning nanochat for about two days on a depth=12 model; as he reports the agent's run, it worked through about 700 changes autonomously and found about 20 that improved validation loss ([[x-2026-03-09-autoresearch-tuning-nanochat]] #1). He tested them himself: all were additive and transferred to depth=24, and stacked they cut the leaderboard's "Time to GPT-2" from 2.02 to 1.80 hours; see [[autoresearch-found-real-improvements-to-nanochat]] ([[x-2026-03-09-autoresearch-tuning-nanochat]] #1). He calls this "round 1", links the nanochat commit, says he is starting "round 2", and is looking in parallel at how multiple agents can collaborate to unlock parallelism ([[x-2026-03-09-autoresearch-tuning-nanochat]] #1). His prediction from it is [[all-frontier-labs-will-autoresearch]] ([[x-2026-03-09-autoresearch-tuning-nanochat]] #1). **Note:** this is not the run in the agent's session report above (126 experiments, about 10.5 hours, the repo's own training script); the numbers are not merged and neither confirms the other ([[github-2026-03-08-autoresearch-session-report]] §Metadata; [[x-2026-03-09-autoresearch-tuning-nanochat]] #1).

**In the Skill Issue interview (2026-03-20).** He calls autoresearch an implication of taking himself out of the loop: "here's an objective, here's a metric, here's your boundaries" of what it can and cannot do, and go; he says it worked, which he did not expect; see [[take-yourself-out-of-the-agent-loop]] ([[talk-2026-03-20-skill-issue]] @17:00, @17:32). Left overnight on nanochat, which he had tuned by hand in the way he has worked for two decades, it came back with tunings he had not seen: he had forgotten weight decay on the value embeddings and his Adam betas were not sufficiently tuned, and these interact ([[talk-2026-03-20-skill-issue]] @18:04, @18:36). That is a single loop; labs with tens of thousands of GPUs could run far more ([[talk-2026-03-20-skill-issue]] @19:08). `program.md` is, in his words, his crappy attempt at describing how the autoresearcher should work; he imagines a research organisation described by markdown files, whose code could itself be tuned ([[talk-2026-03-20-skill-issue]] @20:46, @21:19, @21:51). He is working on parallelising it with an untrusted pool of internet workers whose candidate commits trusted workers verify, since a good commit is expensive to find but cheap to check ([[talk-2026-03-20-skill-issue]] @33:20, @33:53, @34:57). It suits only what can be evaluated; see [[autoresearch-needs-an-objective-metric]] ([[talk-2026-03-20-skill-issue]] @24:02).
