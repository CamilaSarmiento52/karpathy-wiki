# Tokenization
To tokenize, in his words, is to convert raw text into a sequence of integers according to a vocabulary of possible elements ([[youtube-2023-01-17-gpt-from-scratch]] @09:31).

## What he says
The GPT lecture uses a character-level tokenizer: a lookup table from each of the 65 characters in tiny Shakespeare to an integer and back ([[youtube-2023-01-17-gpt-from-scratch]] @08:59, @10:35). Sub-word tokenizers such as Google's SentencePiece and OpenAI's tiktoken (byte-pair encoding, used by GPT) encode neither whole words nor single characters, and are what is usually adopted in practice ([[youtube-2023-01-17-gpt-from-scratch]] @10:35, @11:10). The GPT-2 encoding has roughly 50,000 tokens, so "hi there" becomes three integers instead of eight ([[youtube-2023-01-17-gpt-from-scratch]] @11:43). You can trade off codebook size against sequence length: small vocabularies give long sequences, large vocabularies give short ones ([[youtube-2023-01-17-gpt-from-scratch]] @11:43, @12:16). He keeps the character-level tokenizer because it is the simplest thing, accepting very long sequences ([[youtube-2023-01-17-gpt-from-scratch]] @12:16). Because OpenAI uses sub-word tokens, the Shakespeare set would be around 300,000 tokens in their vocabulary rather than 1 million characters ([[youtube-2023-01-17-gpt-from-scratch]] @1:49:47).

minGPT ships the sub-word side: its `bpe.py` is a mildly refactored Byte Pair Encoder that translates between text and sequences of integers exactly as OpenAI did in GPT ([[github-2023-01-08-mingpt-readme]] §intro).

In the CS25 lecture he repeats that Transformers need text encoded as integers, in the simplest case one integer per character so the whole text becomes one long one-dimensional sequence ([[talk-2023-05-19-stanford-cs25-transformers]] @31:35, @32:07). With multiple documents people splice in special end-of-text tokens, which have no modelling effect beyond the Transformer learning that the token means wipe the memory ([[talk-2023-05-19-stanford-cs25-transformers]] @32:07, @32:40). Real models' tokens, he notes in passing, are usually BPE, SentencePiece or WordPiece tokens ([[talk-2023-05-19-stanford-cs25-transformers]] @42:39).

In State of GPT he describes tokenization as the step before training that turns raw text into integer sequences, the native representation GPTs work over ([[talk-2023-05-25-state-of-gpt]] @02:16, @02:48). He calls it a lossless translation between text, tokens and integers, with several algorithms available, for example byte pair encoding, which iteratively merges text chunks into tokens ([[talk-2023-05-25-state-of-gpt]] @02:48). Vocabularies are usually a couple of tens of thousands of tokens; his example distribution has 50,257 entries ([[talk-2023-05-25-state-of-gpt]] @03:21, @06:13).

The Zero to Hero README calls the tokenizer a necessary and pervasive component of LLMs that translates between strings and tokens, which are text chunks ([[github-2024-02-20-nn-zero-to-hero-readme]] §intro, Lecture 8). It describes tokenizers as a completely separate stage of the LLM pipeline, with their own training sets and training algorithm (Byte Pair Encoding), that after training implement `encode()` from strings to tokens and `decode()` back ([[github-2024-02-20-nn-zero-to-hero-readme]] §intro, Lecture 8).

**Let's build the GPT Tokenizer (February 2024).** He opens the lecture by calling tokenization his least favourite part of working with LLMs, necessary to understand because it is hairy, full of hidden foot guns, and behind a lot of LLM oddness ([[youtube-2024-02-20-gpt-tokenizer]] @00:00). Tokens are the fundamental unit, the atom, of LLMs: tokenization translates strings into token sequences and back, and each token's integer indexes a row of a trainable embedding table, which is how the Transformer perceives it ([[youtube-2024-02-20-gpt-tokenizer]] @01:40, @02:12, @03:20). He credits the GPT-2 paper as probably the one that introduced byte-level encoding for LLM tokenization; GPT-2 has a 50,257-token vocabulary and a 1,024-token context ([[youtube-2024-02-20-gpt-tokenizer]] @02:45, @03:20).

**What a tokenizer app shows.** The same word becomes different tokens depending on a leading space, its position and its case, so the model must learn from data that "egg", " egg" and "Egg" are the same concept ([[youtube-2024-02-20-gpt-tokenizer]] @07:47, @08:21, @08:54). Numbers split arbitrarily, 127 as one token and 677 as two ([[youtube-2024-02-20-gpt-tokenizer]] @07:12, @07:47). The same string drops from 300 GPT-2 tokens to 185 with the GPT-4 tokenizer, whose vocabulary is roughly twice as large, and GPT-4 groups runs of spaces into single tokens, which he calls a deliberate choice by OpenAI that densifies Python ([[youtube-2024-02-20-gpt-tokenizer]] @12:17, @12:51, @13:58, @14:32). More tokens are not infinitely better, because the embedding table and the output softmax grow; there is a sweet spot where everything is appropriately dense and still fairly efficient ([[youtube-2024-02-20-gpt-tokenizer]] @13:26).

**Why bytes.** Python strings are sequences of Unicode code points, about 150,000 characters across 161 scripts ([[youtube-2024-02-20-gpt-tokenizer]] @15:41, @16:14). He rejects code points as tokens because the vocabulary would be large and, more worryingly, the standard keeps changing, so it is not a stable representation ([[youtube-2024-02-20-gpt-tokenizer]] @17:20, @17:54). He sticks with UTF-8, which encodes each code point as one to four bytes and, unlike UTF-16 and UTF-32, is backwards compatible with ASCII ([[youtube-2024-02-20-gpt-tokenizer]] @18:30, @19:39, @20:45). Raw bytes alone give a vocabulary of only 256 and sequences far too long for a finite attention context, so BPE compresses the byte sequences ([[youtube-2024-02-20-gpt-tokenizer]] @21:20, @21:52, @22:26).

**Training BPE.** On Wikipedia's toy example he finds the most frequent pair, mints a new token for it, replaces every occurrence and repeats ([[youtube-2024-02-20-gpt-tokenizer]] @23:32, @24:06, @24:41). On bytes you start from 256 tokens and iteratively mint new ones, ending with a compressed training set and a way to encode and decode any sequence ([[youtube-2024-02-20-gpt-tokenizer]] @26:21). In his notebook the top pair was "e" followed by a space, occurring 20 times; merging it into token 256 shortened the sequence by exactly those 20 ([[youtube-2024-02-20-gpt-tokenizer]] @29:41, @30:14, @33:33). The number of merges is a hyperparameter: more merges give a larger vocabulary and shorter sequences, and GPT-4 uses roughly 100,000 tokens ([[youtube-2024-02-20-gpt-tokenizer]] @34:06, @34:39). New tokens are themselves eligible for merging, so the result is a binary forest over the bytes; twenty merges gave a compression ratio of about 1.27 ([[youtube-2024-02-20-gpt-tokenizer]] @36:53, @38:01, @38:33). The tokenizer's parameters are just this merges dictionary ([[youtube-2024-02-20-gpt-tokenizer]] @57:03).

**A separate stage.** He stresses that the tokenizer is a completely separate object from the LLM: a pre-processing stage run once, with its own training set of documents that may differ from the LLM's ([[youtube-2024-02-20-gpt-tokenizer]] @39:06, @39:38). Typically all the LLM's training data is tokenized once and the model reads the stored tokens ([[youtube-2024-02-20-gpt-tokenizer]] @40:45, @41:19). The mix of languages and code in the tokenizer's training set decides how many merges each gets, and so how densely that data sits in token space; more Japanese data means shorter Japanese sequences, which helps the LLM's finite context ([[youtube-2024-02-20-gpt-tokenizer]] @41:19, @41:53, @42:25).

**Decode and encode.** Decode maps each token to its bytes, joins them and decodes UTF-8; because not every byte sequence is valid UTF-8 he passes `errors="replace"`, as OpenAI's code does, so a replacement character in output means the model emitted an invalid sequence ([[youtube-2024-02-20-gpt-tokenizer]] @42:59, @44:41, @45:16, @47:32, @48:05). Encode turns text into bytes and repeatedly applies the eligible merge learned earliest ([[youtube-2024-02-20-gpt-tokenizer]] @48:38, @50:22, @50:57). Encoding then decoding returns the original string, even on unseen text, but decoding then encoding is not an identity ([[youtube-2024-02-20-gpt-tokenizer]] @55:56, @56:30).

**Regex pre-split.** The GPT-2 paper argues that naive BPE would merge words with punctuation, as in "dog." and "dog!", so OpenAI enforce rules about what never merges ([[youtube-2024-02-20-gpt-tokenizer]] @58:09, @58:43). GPT-2's `encoder.py` splits text into chunks with a regex, tokenizes each chunk independently and concatenates the results, so merges never cross chunk boundaries ([[youtube-2024-02-20-gpt-tokenizer]] @59:51, @1:03:13, @1:03:47, @1:04:21). He finds its apostrophe handling extremely gnarly and slightly gross: hard-coded to the ASCII apostrophe, broken on uppercase, probably language-specific ([[youtube-2024-02-20-gpt-tokenizer]] @1:05:28, @1:06:00, @1:06:34, @1:07:10). Runs of spaces are never merged in GPT-2, so some further unstated rule was enforced; OpenAI released inference code, not the tokenizer's training code ([[youtube-2024-02-20-gpt-tokenizer]] @1:10:00, @1:10:35, @1:11:08). The GPT-4 pattern is case-insensitive, handles whitespace differently and only merges numbers of up to three digits, and he says nobody really knows why because none of it is documented ([[youtube-2024-02-20-gpt-tokenizer]] @1:12:51, @1:13:58, @1:14:31).

**OpenAI's code and tiktoken.** tiktoken is OpenAI's official, inference-only tokenization library ([[youtube-2024-02-20-gpt-tokenizer]] @1:11:42). GPT-2's `encoder.json` and `vocab.bpe` are exactly his `vocab` and `merges`, which are all you need to represent a tokenizer; their extra byte encoder layer is to him a spurious implementation detail, and the code is otherwise algorithmically identical to what he built ([[youtube-2024-02-20-gpt-tokenizer]] @1:15:05, @1:15:36, @1:16:11, @1:16:44, @1:17:50).

**Special tokens.** GPT-2's 50,257 tokens are 256 byte tokens, 50,000 merges and one special token, `<|endoftext|>`, inserted between documents, whose meaning the model has to learn from data ([[youtube-2024-02-20-gpt-tokenizer]] @1:18:58, @1:19:34, @1:20:07). Special tokens bypass BPE and are swapped in by special-case handling ([[youtube-2024-02-20-gpt-tokenizer]] @1:20:39, @1:21:15). They are used pervasively in finetuning to delimit conversations, and GPT-4 adds fill-in-the-middle tokens ([[youtube-2024-02-20-gpt-tokenizer]] @1:21:49, @1:22:24, @1:24:03). Adding one means extending the embedding table and the output layer, model surgery he calls a very common operation ([[youtube-2024-02-20-gpt-tokenizer]] @1:24:37, @1:25:09).

**SentencePiece.** SentencePiece, used by Llama and Mistral, does both training and inference efficiently ([[youtube-2024-02-20-gpt-tokenizer]] @1:28:35, @1:29:09). The big difference from tiktoken is that it runs BPE on code points and, for rare code points, maps them to an unknown token or, with byte fallback on, to byte tokens ([[youtube-2024-02-20-gpt-tokenizer]] @1:29:09, @1:29:42, @1:30:16). He configured it to match how Llama 2 trained its tokenizer, as far as he could tell, by reading the options out of Meta's model file ([[youtube-2024-02-20-gpt-tokenizer]] @1:32:27). He would rather not normalise the raw text at all, as a deep learning person, and would rather treat a file as one stream of bytes than adopt SentencePiece's concept of sentences ([[youtube-2024-02-20-gpt-tokenizer]] @1:33:01, @1:34:04, @1:34:36). With byte fallback off, an unseen Korean string became one unknown token, which is why he thinks Llama correctly turned it on ([[youtube-2024-02-20-gpt-tokenizer]] @1:39:10, @1:39:44). He sums it up as commonly used and efficient but full of historical baggage and quirks, and not well documented ([[youtube-2024-02-20-gpt-tokenizer]] @1:42:36, @1:43:09).

**Vocabulary size.** In a GPT the vocabulary size appears only in the token embedding table and the final `lm_head` layer ([[youtube-2024-02-20-gpt-tokenizer]] @1:43:40, @1:44:13, @1:44:46). A larger vocabulary costs compute, leaves rare tokens undertrained and may squash too much into one token for the forward pass, while shorter sequences let the model attend to more text ([[youtube-2024-02-20-gpt-tokenizer]] @1:45:18, @1:45:51, @1:46:26). He calls it mostly an empirical hyperparameter, usually in the high tens of thousands or around 100,000 in state-of-the-art models ([[youtube-2024-02-20-gpt-tokenizer]] @1:46:26). Extending a pretrained model's vocabulary is mild model surgery, often done with the base model frozen ([[youtube-2024-02-20-gpt-tokenizer]] @1:46:58, @1:47:32). He presents gist tokens, from a paper he cites, as one point in a larger design space of new tokens ([[youtube-2024-02-20-gpt-tokenizer]] @1:48:04, @1:49:45). He thinks many people are converging on keeping the Transformer and tokenizing other modalities, citing an early image paper and Sora's visual patches ([[youtube-2024-02-20-gpt-tokenizer]] @1:50:18, @1:50:52, @1:51:24).

**The failures he traces to tokenization.** He opens with a list of LLM problems he says trace back to tokenization, advising that many issues that look like problems of the architecture or the LLM itself are tokenization issues, and returns at the end to explain each ([[youtube-2024-02-20-gpt-tokenizer]] @04:27, @05:00, @05:33, @1:51:24). The root cause, he says, is that the LLM works on tokens, text chunks that are its atoms, not characters as people think of them ([[youtube-2024-02-20-gpt-tokenizer]] @2:01:10).

- **Spelling and string processing.** ".DefaultCellStyle" is a single GPT-4 token, so he suspected too much is crammed into it; GPT-4 miscounted its letter "l" (he hedges that he may have miscounted himself) and could not reverse it directly, but succeeded after first listing the characters separated by spaces ([[youtube-2024-02-20-gpt-tokenizer]] @1:51:58, @1:52:34, @1:53:44).
- **Non-English languages.** Beyond the model seeing less non-English data, the tokenizer is not sufficiently trained on it: "Hello how are you" is 5 tokens and its translation 15, and even the common Korean hello is three tokens ([[youtube-2024-02-20-gpt-tokenizer]] @1:54:20, @1:54:53). English gets longer tokens, so other languages bloat their sequences and use up context ([[youtube-2024-02-20-gpt-tokenizer]] @09:59, @10:33, @11:05).
- **Simple arithmetic.** Addition is a digit-level algorithm, but numbers are split arbitrarily by whatever happened to merge, as a blog post he cites shows for four-digit numbers; he calls this a headwind, and says Llama 2 splits all digits partly to improve simple arithmetic ([[youtube-2024-02-20-gpt-tokenizer]] @1:55:27, @1:56:02, @1:56:36).
- **Python in GPT-2.** Partly a modelling issue, but partly tokenization: every indentation space is its own GPT-2 token, which dramatically reduces the context the model can attend to, almost a tokenization bug that GPT-4 fixed ([[youtube-2024-02-20-gpt-tokenizer]] @1:56:36, @1:57:09). He says much of the Python improvement from GPT-2 to GPT-4 comes from the tokenizer's design, not only from the model and its optimisation ([[youtube-2024-02-20-gpt-tokenizer]] @14:32).
- **Halting at `<|endoftext|>` (added in the closing walkthrough).** Asked to print the string, GPT-4 failed; he does not know what OpenAI does under the hood, but suspects special tokens are being parsed from attacker-controlled user input, which would make them an attack surface ([[youtube-2024-02-20-gpt-tokenizer]] @1:57:09, @1:57:44, @1:58:18).
- **Trailing whitespace.** GPT tokens carry their leading space, so a prompt ending in a space adds a lone space token that splits the next token and puts the model out of distribution, hence the playground's warning ([[youtube-2024-02-20-gpt-tokenizer]] @1:58:52, @1:59:26, @2:00:34, @2:01:10).
- **Partial and unstable tokens (added in the closing walkthrough).** Prompting with part of a single token, ".DefaultCellSta", made the model predict a stop sequence at once (an end-of-text token, he thinks) and on retry trip a usage-policy flag; he points to tiktoken's undocumented special-case code for "unstable tokens", which deals with exactly this partial-token problem ([[youtube-2024-02-20-gpt-tokenizer]] @2:01:41, @2:02:14, @2:02:47, @2:03:20, @2:03:53, @2:04:28).
- **SolidGoldMagikarp.** Earlier GPT went off on unrelated tangents when asked about it ([[youtube-2024-02-20-gpt-tokenizer]] @05:33). A blog post found a cluster of such tokens that triggered evasion, hallucination and insults ([[youtube-2024-02-20-gpt-tokenizer]] @2:05:01, @2:05:36, @2:06:09). What is thought to have happened, he says without knowing it was definitively explored, is that a Reddit username was common in the tokenizer's training data but absent from the LLM's, so its token's embedding row was never trained, like unallocated memory in a C program, and invoking it gives undefined behaviour ([[youtube-2024-02-20-gpt-tokenizer]] @2:07:16, @2:07:50, @2:08:24, @2:08:57).
- **JSON versus YAML.** The same data took 116 tokens as JSON and 99 as YAML; since you pay per token in context and money, he advises preferring YAML and measuring the token efficiency of formats ([[youtube-2024-02-20-gpt-tokenizer]] @2:09:31, @2:10:06).

He calls the stage full of foot guns, sharp edges, security issues and AI safety issues, worth understanding even though he personally dislikes it ([[youtube-2024-02-20-gpt-tokenizer]] @2:10:06, @2:10:39). His recommendations: reuse the GPT-4 vocabulary with tiktoken if you can; if you must train your own, use SentencePiece BPE but copy Meta's settings carefully, or wait for minbpe to become efficient ([[youtube-2024-02-20-gpt-tokenizer]] @2:10:39, @2:11:13, @2:11:45). The ideal, which does not exist yet, is tiktoken with training code ([[youtube-2024-02-20-gpt-tokenizer]] @2:12:18).

The Zero to Hero README, describing this lecture, also says many weird LLM behaviours and problems trace back to tokenization and that ideally someone finds a way to delete the stage ([[github-2024-02-20-nn-zero-to-hero-readme]] §intro, Lecture 8).

**The minbpe README (2024-04-22 snapshot).** He writes that BPE was popularised for LLMs by the GPT-2 paper and code release, cites Sennrich et al. 2015 as the original reference for BPE in NLP, and says all modern LLMs, for example GPT, Llama and Mistral, use it to train their tokenizers ([[github-2024-04-22-minbpe-readme]] §intro). A tokenizer's three primary functions are to train the vocabulary and merges on text, encode text to tokens and decode tokens to text ([[github-2024-04-22-minbpe-readme]] §intro). The regex pre-split breaks text into categories such as letters, numbers and punctuation so no merges happen across category boundaries; it was introduced in GPT-2 and is still in use as of GPT-4 ([[github-2024-04-22-minbpe-readme]] §intro). minbpe always allocates the 256 individual bytes as tokens and merges from there, so in Wikipedia's example the first merge becomes token 256 ([[github-2024-04-22-minbpe-readme]] §quick start). As in tiktoken, encoding must explicitly allow special tokens; otherwise, he warns, it can become a major footgun, unintentionally tokenizing attacker-controlled data such as user prompts with special tokens ([[github-2024-04-22-minbpe-readme]] §inference: GPT-4 comparison). To train, use `BasicTokenizer` if you want neither regex splitting nor special tokens, or `RegexTokenizer`, whose default is the GPT-4 pattern, to follow OpenAI's approach, varying the vocabulary size with the size of the dataset ([[github-2024-04-22-minbpe-readme]] §training). Special tokens are registered after the merges, so with a vocabulary of 32,768 the first special token has id exactly 32,768 ([[github-2024-04-22-minbpe-readme]] §training).

**Custom vocabularies for small models (llama2.c).** The default is the Llama 2 tokenizer with 32,000 tokens; for many small "boutique" LLMs he says a vocabulary that big may be overkill and you may be much better off training your own ([[github-2024-05-29-llama2c-readme]] §custom tokenizers). A smaller vocabulary means fewer parameters (a smaller embedding table), faster inference (fewer tokens to predict) and possibly shorter sequences (better compression on your data) ([[github-2024-05-29-llama2c-readme]] §custom tokenizers). `train_vocab` calls sentencepiece's BPE, which starts from raw UTF-8 bytes and repeatedly merges the most common consecutive pairs, with the settings he thinks Meta used; a 4096-token vocabulary trained on TinyStories gives about the same sequence length per example as the 32,000-token Llama 2 tokenizer ([[github-2024-05-29-llama2c-readme]] §custom tokenizers).

**The GPT-2 tokenizer in practice (2024-06-09).** In the GPT-2 lecture the vocabulary of 50,257 is again 50,000 BPE merges, 256 byte tokens and one end-of-text token that delimits documents and can start generation ([[youtube-2024-06-09-reproduce-gpt-2]] @27:59, @28:35). He tokenizes with tiktoken's GPT-2 encoding and points to his tokenization video for detail ([[youtube-2024-06-09-reproduce-gpt-2]] @35:29, @06:39). The GPT-2 tokenizer compresses English roughly 3:1, so 1,000 characters is about 300 tokens, and tiny Shakespeare's roughly 1M characters became 338,000 tokens ([[youtube-2024-06-09-reproduce-gpt-2]] @46:06, @1:05:12, @1:05:47). In his FineWeb-Edu preprocessing every document starts with the end-of-text token (id 50256), despite its name ([[youtube-2024-06-09-reproduce-gpt-2]] @3:15:31). Tokens are stored as uint16 because GPT-2's largest id is well below 65,535 ([[youtube-2024-06-09-reproduce-gpt-2]] @3:16:03, @3:16:39).

**For a general audience (Deep Dive, 2025-02-05).** Neural networks want a one-dimensional sequence over a finite set of symbols, and sequence length is a precious resource to trade against vocabulary size ([[youtube-2025-02-05-deep-dive-into-llms]] @07:48, @08:56, @09:32). He goes from UTF-8 bits to bytes, 256 symbols best thought of as unique IDs, to byte-pair encoding, which mints a new symbol for a common pair and repeats ([[youtube-2025-02-05-deep-dive-into-llms]] @10:06, @10:38, @11:13). About 100,000 symbols is a good vocabulary size in practice; GPT-4 uses 100,277 ([[youtube-2025-02-05-deep-dive-into-llms]] @11:48). He uses the tiktokenizer website to show cl100k_base tokenizations and that they are sensitive to case and whitespace ([[youtube-2025-02-05-deep-dive-into-llms]] @12:19, @12:54, @13:28). Because models see tokens rather than characters, character-level tasks often fail, and he guesses OpenAI may have hardcoded the answer to the r's in "strawberry"; the failures are on [[a-lot-of-llm-oddness-traces-back-to-tokenization]] ([[youtube-2025-02-05-deep-dive-into-llms]] @2:01:07, @2:03:51, @2:04:25). Audio, as slices of a spectrogram, and images, as patches, can be tokenized and interleaved with text in one model, so he does not see multimodality as a fundamental change ([[youtube-2025-02-05-deep-dive-into-llms]] @3:10:20, @3:10:53).

**The chat as a token window (How I use LLMs, 2025-02-27).** Under the hood his haiku request is 15 tokens in Tiktokenizer, from a GPT-4o vocabulary of roughly 200,000 ([[youtube-2025-02-27-how-i-use-llms]] @03:57). A conversation adds special tokens marking where user and assistant messages begin and end; his two chat bubbles came to 42 tokens ([[youtube-2025-02-27-how-i-use-llms]] @05:05, @05:40, @06:15). User and model take turns writing into one one-dimensional token stream, the context window, which he calls the working memory of the conversation; "new chat" resets it, see [[start-a-new-chat-per-topic]] ([[youtube-2025-02-27-how-i-use-llms]] @06:48, @07:21). Audio can be tokenized by quantizing small spectrogram windows into a vocabulary of, say, 100,000 audio chunks, and images by quantizing the patches of a grid; the Transformer does not know which tokens are text, audio or images, only the encoder and decoder do ([[youtube-2025-02-27-how-i-use-llms]] @1:28:08, @1:40:30, @1:41:03, @1:41:36).
