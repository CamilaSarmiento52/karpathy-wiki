# llm-wiki
Raw: [[raw/github/karpathy__gist-442a6bf555914893e9891c11519de94f]] · Original: https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f

## Summary
He calls this an idea file, meant to be pasted to your own LLM agent, which then builds the
specifics with you (§intro). The core idea contrasts RAG, where the LLM rediscovers knowledge
on every question, with an LLM that incrementally builds and maintains a persistent,
interlinked markdown wiki that compounds as sources and questions are added (§The core idea).
There are three layers, immutable raw sources, an LLM-owned wiki and a schema document, and
three operations, ingest, query and lint, supported by a content index and a chronological
log (§Architecture, §Operations, §Indexing and logging). He suggests search tools for when the
wiki grows, Obsidian tips, and argues the pattern works because LLMs make the bookkeeping that
makes humans abandon wikis nearly free, relating it to Vannevar Bush's Memex (§Optional: CLI
tools, §Tips and tricks, §Why this works). He closes by saying the document is deliberately
abstract and everything in it optional (§Note).

## Key points
- The pattern: three layers, ingest/query/lint, compounding instead of re-deriving → [[llm-knowledge-bases]]
- The workflow, with a schema step, one-at-a-time ingest, index and log → [[llm-wiki-workflow]]
- RAG rediscovers; the wiki accumulates → [[a-wiki-compounds-where-rag-rediscovers]]
- An index file is enough at moderate scale; search as it grows → [[an-index-file-avoids-rag-at-moderate-scale]], [[no-rag-needed-for-a-small-wiki]]
- LLMs make wiki maintenance nearly free → [[llms-make-wiki-maintenance-nearly-free]]

### topic (existing): llm-knowledge-bases
- existing: yes (aliases include "LLM Wiki")
- statements:
  - He calls this a pattern for building personal knowledge bases with LLMs, and the document an idea file to paste to your own agent, which builds the specifics with you (§intro).
  - The core idea: rather than retrieving from raw documents at query time, the LLM incrementally builds and maintains a persistent wiki between you and the sources, integrating each new source into existing pages, so knowledge is compiled once and kept current (§The core idea).
  - You rarely or never write the wiki; you source, explore and ask; the LLM does the summarizing, cross-referencing, filing and bookkeeping (§The core idea).
  - Uses he lists: personal tracking, research over weeks or months, a companion wiki for a book, a team wiki fed by Slack, meetings and calls with humans possibly reviewing, and others (§The core idea). [examples]

  - He relates the idea in spirit to Vannevar Bush's Memex (1945), a private, curated store where connections matter as much as documents; the part Bush could not solve, he says, was who does the maintenance (§Why this works).
  - The human's job is to curate sources, direct the analysis, ask good questions and think about meaning; the LLM's job is everything else (§Why this works).
  - The document is intentionally abstract: directory structure, schema conventions, page formats and tooling depend on your domain and LLM, and all of it is optional (§Note).

### method (existing): llm-wiki-workflow
- existing: yes (aliases: LLM Wiki pattern); built from the post
- proposed additions (merge decides how many go into `steps`):
  - **Schema.** Keep a schema document (e.g. CLAUDE.md or AGENTS.md) telling the LLM the wiki's structure, conventions and workflows; you and the LLM co-evolve it (§Architecture).
  - **Ingest one at a time.** The LLM reads the source, discusses key takeaways with you, writes a summary page, updates the index and the relevant pages, and appends to the log; one source might touch 10–15 pages (§Operations). [10–15: example] He prefers one source at a time, staying involved; batch ingest with less supervision is an option (§Operations).
  - **Query from the index.** The LLM reads `index.md` first, then the relevant pages, and answers with citations; good answers are filed back as new pages (§Indexing and logging, §Operations).
  - **Log.** Append each ingest, query and lint to `log.md` with a consistent prefix so simple unix tools can parse it (§Indexing and logging).
  - **Lint.** Contradictions, stale claims, orphan pages, concepts without pages, missing cross-references, data gaps (§Operations).
  - **Search when it grows.** The index suffices at small scale; add proper search such as qmd, or a vibe-coded naive script, as the wiki grows (§Optional: CLI tools).
- relation: method update; the existing six steps stay, cited to the post.
- **Caution:** our CLAUDE.md has steps with the same names; cite only the gist, and only for what it says.
